# my1010 (1010! + Sudoku)

Flutter + Riverpod 3 + SharedPreferences + Firebase (Firestore, anonymous Auth).

## Commands
- `flutter pub get`
- `dart format lib test` (CI fails on unformatted code)
- `flutter analyze` (must report no issues)
- `flutter test`

## Architecture
Modules are layered `core ← features ← games ← app.dart`; `test/architecture_test.dart`
enforces it.
- `lib/core/`: shared infrastructure. `firebase/` (bootstrap, `LeaderboardRepository` +
  Firestore/in-memory impls), `ui_kit/theme/` (palettes, theme picker), `routing/`,
  `game/game_interface.dart`, `storage/`. Never imports features or games.
- `lib/features/`: cross-game features (`home/`, `leaderboard/`). Never import games.
- `lib/games/<game>/`: isolated game modules with `domain` / `data` / `presentation`.
  Games never import each other. Register games in `lib/games/game_registry.dart`.
- `lib/app.dart` is the composition root: it builds the routes (`/`, `/games/<id>`,
  `/leaderboard/<gameId>`) from the `GameInterface` list.
- `games/*/domain` is pure Dart (no Flutter imports; `package:meta` only). Keep it that way.
- 1010! modes: subclass `GameMode` in `games/original_game/domain/game_mode.dart`, register in
  `GameModes.all`. `OriginalGame.id` stays `classic` so existing leaderboard entries remain valid.
- `sharedPreferencesProvider` is overridden in `main()` and tests; `leaderboardRepositoryProvider`
  (core/firebase) defaults to the in-memory repo and is overridden with Firestore when Firebase
  initializes. Firestore docs keep the `modeId` field name (it holds the game id) to match the
  deployed `firestore.rules`.
- `lib/firebase_options.dart` is generated by `flutterfire configure` (project `my1010-e4142`).
- The display name is `my1010`, but the Android applicationId / iOS bundle id stay
  `com.elaybarlev.ten_ten_clone`: changing them breaks Firebase and Obtainium updates.
- App icons are generated by `flutter test tool/icon/generate_icons_test.dart`.
